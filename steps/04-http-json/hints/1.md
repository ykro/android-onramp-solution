# Pista 1. Cuatro caminos de una llamada

Una llamada HTTP puede terminar de cuatro formas: el servidor no contesta (`IOException`, que conviertes en `NetworkError`), responde con un código de error (`HttpError`), responde con un cuerpo JSON que no se puede leer (`ParseError`) o devuelve la lista de libros (`Success`). Envuelve el request para atrapar `IOException`, revisa el código antes de leer el cuerpo y después decodifica.

Por defecto, `kotlinx.serialization` falla cuando el JSON trae un campo que la clase no declara. Busca en la [guía de JSON](https://github.com/Kotlin/kotlinx.serialization/blob/master/docs/json.md#ignoring-unknown-keys) cómo cambiar eso.

Si ya tienes claros los cuatro caminos, abre [la pista 2](2.md).
