# Pista 2. Qué usar en cada ejercicio

- Ejercicio 1. Cambia la línea que elige el libro para que pase por el `BookPicker`. Después mete la elección y el `update` en un `viewModelScope.launch { }` que empiece con `delay(SUGGEST_DELAY_MS)`.
- Ejercicio 2. Renombra el `MutableStateFlow` a uno privado y expón otro valor de tipo `StateFlow` con `asStateFlow()`. Para marcar como leído, avisa al repositorio y usa `update { it.copy(...) }`. `lista - elemento` devuelve una lista nueva sin ese elemento, y `takeIf { }` devuelve `null` cuando la condición no se cumple.
- Ejercicio 3. Borra la copia y lee `state.suggestion` directo. `Button` tiene un parámetro `enabled`. Para que un botón solo aparezca con sugerencia, ponlo dentro de un `if` o de un `?.let`.
- Ejercicio 4. Para lo que debe existir una sola vez en la app usa `single`, y pon entre `< >` el tipo que pide el constructor del ViewModel (la interfaz, no la clase concreta). Para el ViewModel, Koin tiene `viewModelOf`, en `org.koin.core.module.dsl`. Revisa qué implementación de cada interfaz trae `ShelfData.kt`.

Si quieres ver la forma, abre [la pista 3](3.md).
